01

RocketLLM

Domain
AI systems · Inference engineering
What it is
A local inference engine that runs language models bigger than the graphics card they are loaded onto. Rather than holding every weight in video memory at once, it streams them through a fixed memory window and fetches the next layer while the current one is still computing, so the copying hides behind the arithmetic. It exposes an OpenAI-compatible API, which means existing tools can point at it without being modified.
Mechanism
Asynchronous layer prefetching across the PCIe bus, tiered caching, fused expert fetching for mixture-of-experts models, and speculative decoding.
Trade-off
Streaming weights spends bus bandwidth, so throughput stays below a model that fits entirely in VRAM. The point is that the model runs at all on hardware that could not otherwise host it.

02

Meridian

Domain
Full-stack · Multi-tenant SaaS
What it is
A multi-tenant business dashboard and CRM — the kind of product where one company must never see another company's data. Instead of trusting every query to remember its filter, the isolation is enforced inside the database itself, so a query that forgets returns nothing at all rather than quietly leaking. Authentication, user roles and subscription billing all sit behind the same boundary.
Mechanism
Postgres row-level security bound to a session-scoped tenant context, with role-based access control and Stripe subscription lifecycle handling on top.
Trade-off
Every connection has to establish its tenant context before it can read anything, which complicates connection pooling and makes ad-hoc queries harder to write by hand.

03

Marginalia

Domain
AI retrieval · Document Q&A
What it is
A document question-answering portal that will not answer without showing its working. You upload PDFs and ask questions in ordinary language; every part of the reply links back to the passage it came from, highlighted in a viewer sitting beside the text. An answer that cannot be traced to a source does not get shown at all, which is the whole reason the project exists.
Mechanism
Keyword and vector search run in parallel and their rankings are merged by reciprocal rank fusion; citations are then validated on the server against the source text before the answer is released.
Trade-off
Validation adds latency to every response, and it will occasionally discard a correct answer whose supporting passage was phrased too loosely to match.

04

Openings

Domain
Full-stack · Scheduling
What it is
A booking engine for services where two people clicking at the same instant must not walk away with the same slot. The obvious approach — check whether the time is free, then write the booking — fails quietly under real traffic, because neither request can see the other one in flight. Here the database refuses the overlap outright, and the application's job is only to turn that refusal into a sensible message.
Mechanism
An exclusion constraint over time ranges makes an overlapping booking impossible to store; temporary slot holds and time-zone-correct server scheduling sit on top of it.
Trade-off
Competing writes on the same resource serialise, so a rush on one popular slot is slower than a naive insert would be — and correct, which the naive insert is not.

05

Counter

Domain
Full-stack · E-commerce
What it is
An online storefront with the merchant's admin portal attached. Its central problem is the one every shop meets on a busy day: two customers checking out the last item at the same moment, both told it is theirs. Counter reserves stock atomically at checkout and calculates every price on the server, so the amount a customer is charged is never something the browser got to decide.
Mechanism
Conditional atomic stock decrements with time-limited reservations, server-authoritative pricing, and split tag caching with live stock updates.
Trade-off
Reservations expire on a timer, so an abandoned checkout holds real inventory for a short window. That was chosen deliberately over the alternative, which is overselling.

PARSA-RAG

Domain
AI retrieval · Right-to-left language NLP
What it is
A question-answering system for technical and engineering documents written in a right-to-left language. Those documents defeat ordinary search for several reasons at once: the text runs the other way, words join and break in ways Latin-script tooling does not anticipate, and the content that matters is often locked inside tables and diagrams rather than sentences. PARSA-RAG reads the page layout first, describes charts so they can be searched as text, and sends each question to the subject area it belongs to.
Mechanism
Structure-aware document parsing, vision-model chart captioning, hybrid dense and learned-sparse retrieval with cross-encoder reranking, and subject-scoped vector collections.
Trade-off
Parsing and captioning must finish before anything becomes searchable, so ingesting a document library is an overnight job rather than an instant upload.

MaintAdapt

Domain
Data science · Predictive maintenance
What it is
A study of when a jet engine should come off the wing. Pull it too late and it fails in service, which costs far more than any workshop visit; pull it too early and you throw away flying hours it still had. MaintAdapt treats remaining-useful-life prediction as an input to that decision rather than a leaderboard score — models are compared against classical baselines, their stated confidence is checked against what actually happened, and predictions are turned into an alarm threshold under an openly stated cost model.
Evidence
On NASA's C-MAPSS turbofan fleets, alarming on predicted remaining life cuts expected maintenance cost per engine by 61–73% against running to failure and by 44–60% against the best fixed schedule. Alarming on the lower edge of a calibrated interval does better again, at 64–75%.
Trade-off
Those figures depend on an assumed cost ratio between an unplanned failure and a wasted cycle. It is stated rather than buried — move the ratio and the best threshold moves with it.
Source → PythonXGBoostscikit-learn

AdversarialLab

Domain
ML research · Adversarial robustness
What it is
A benchmark built to find out whether a model's claimed robustness is real. Published defences often look strong against the attack they were tuned on and collapse against a stronger one, usually because the attack's gradients were obscured rather than the model genuinely improved. This project re-runs defences under explicit threat models, and puts every result through a four-part sanity suite designed to catch that failure before a number is allowed to count.
Mechanism
Adversarial training and TRADES on CIFAR-10 and MNIST, evaluated under FGSM, PGD and AutoAttack with gradient-masking diagnostics.
Trade-off
Honest evaluation lowers the headline numbers, and it makes the clean-accuracy cost of robustness impossible to hide. That is the point of running it.
Source → PythonPyTorch

Web-Vibe-Security

Domain
Security · Static analysis
What it is
Guardrails and audit tooling for web applications written largely by AI coding assistants. The mistakes in that code are strikingly consistent: secrets that end up in the browser bundle, database access rules that were generated but never switched on, endpoints that trust an identifier handed to them by the client, and imported package names nobody ever published. This ships deterministic checks and drop-in configurations for the common assistants so those failures are caught before they reach production.
Mechanism
Static analysis rules, agent configuration presets and an auditable check suite — not a model asked to review its own output.
Trade-off
Deterministic rules only find the classes of bug they were written for. This narrows a predictable attack surface; it is not a substitute for a real security review.

10

App-Vibe-Security

Domain
Security · Mobile and desktop
What it is
The same idea pointed at mobile and desktop applications. AI-generated app code has its own recurring weak points: desktop shells that let web content reach the operating system, channels between processes that accept whatever they are sent, credentials written to disk in plain text, and deep links another app can forge. The toolkit audits for those patterns across the common cross-platform frameworks.
Mechanism
Zero-trust defaults and automated checks covering React Native, Flutter, Android, iOS and Electron projects.
Trade-off
Coverage is broad but deliberately shallow: it flags structural mistakes, not logic bugs specific to one application.

3D Particle Landing

Domain
Creative front-end · WebGL
What it is
A scroll-driven landing page for an AI learning platform, built to show what the front end can do when restraint is not the brief. One cloud of particles morphs between a brain, a light bulb and a globe as you scroll, and every particle is a hollow triangle that spins on its own axis rather than a dot. It is three static files with no build step, no bundler and no backend.
Mechanism
A single Three.js point cloud holding three sets of positions in one buffer, blended in a custom vertex shader by scroll progress with per-particle stagger.
Trade-off
It is a deliberate showpiece — heavier than its content strictly needs, and the opposite discipline to everything else listed here.
