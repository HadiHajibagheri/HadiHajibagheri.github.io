Profile

Hadi Hajibagheri Engineer

I build two kinds of thing: web systems whose correctness is enforced by the database rather than hoped for in application code, and machine-learning systems that are measured carefully enough to be believed.

Most of my work starts from a constraint somebody else treated as fixed — a graphics card too small for the model, a booking table that double-books under load, an answer nobody can trace back to a source — and ends with that constraint moved somewhere it can actually be enforced.

I design and build interfaces for right-to-left languages such as Arabic as well as left-to-right ones, so mirrored layout, bidirectional text and script-specific typography are part of how I work rather than a retrofit.

Four things I keep having to get right
02.1 PCIe 4.0 ×16 Async H2D copy INT4 · INT8 KV-cache budget

02.1Memory under a hard ceiling

A 13-billion-parameter model does not fit in 8 GB. It fits in 8 GB if you stop treating the weights as resident and start treating them as a stream. RocketLLM fetches layer n+1 across the bus while layer n is still computing, so the copy hides behind the arithmetic. The budget is fixed; what moves through it is scheduled.

02.2 Row-level security EXCLUDE USING GIST tsrange SET LOCAL

02.2Invariants the database enforces

One request cannot see another request's uncommitted rows, which is exactly why “check whether it is free, then write it” fails the moment real traffic arrives. The fix is to make the bad state impossible to store: row-level security so a forgotten tenant filter returns nothing instead of leaking, and an exclusion constraint so two overlapping bookings are refused by the engine itself. The database says no, so the code does not have to remember to.

02.3 BM25 · dense Reciprocal rank fusion Cross-encoder rerank Span citations

02.3Retrieval you can audit

A confident answer with no provenance is indistinguishable from an invented one. Keyword search and meaning-based search surface different documents, so both run and their rankings are merged rather than chosen between. What comes back is then checked against the source text on the server, so every claim arrives attached to a passage you can open and read for yourself.

02.4 FGSM · PGD · AutoAttack TRADES Gradient masking Domain adaptation

02.4Models under attack, and under drift

Robustness is easy to report and easy to get wrong: gradient masking will hand you a model that looks defended right up until someone runs a stronger attack. So the threat model is stated explicitly, defences are re-run under AutoAttack, and a four-part sanity suite has to pass before a number is allowed to count. The same scepticism applies to drift — a model trained on one operating regime is tested on a different one.

01

RocketLLM

What it is
A local inference engine that runs language models bigger than the graphics card they are loaded onto. Rather than holding every weight in video memory at once, it streams them through a fixed memory window and fetches the next layer while the current one is still computing. It exposes an OpenAI-compatible API, so existing tools can point at it unchanged.
Mechanism
Asynchronous layer prefetching across the bus, tiered caching, fused expert fetching for mixture-of-experts models, and speculative decoding.
Trade-off
Streaming weights spends bus bandwidth, so throughput stays below a model that fits entirely in VRAM. The point is that the model runs at all on hardware that could not otherwise host it.

02

Meridian

What it is
A multi-tenant business dashboard and CRM — the kind of product where one company must never see another company's data. Instead of trusting every query to filter correctly, the isolation is enforced inside Postgres, so a forgotten filter returns nothing rather than leaking. Authentication, roles and billing all sit behind the same boundary.
Mechanism
Row-level security bound to a session-scoped tenant context, with role-based access control and Stripe subscription lifecycle on top.
Trade-off
Every connection must establish its tenant context before it can read anything, which complicates connection pooling and makes some ad-hoc queries harder to write by hand.

03

Marginalia

What it is
A document question-answering portal that will not answer without showing its working. You upload PDFs and ask questions in plain language; every part of the reply links back to the passage it came from, highlighted in a viewer beside the text. An answer that cannot be traced to a source does not get shown.
Mechanism
Keyword and vector search run in parallel and are merged by reciprocal rank fusion; citations are then validated server-side against the source before the answer is released.
Trade-off
Validation adds latency to every response, and it will occasionally discard a correct answer whose supporting passage was phrased too loosely to match.

04

Openings

What it is
A booking engine for services where two people clicking at the same instant must not walk away with the same slot. The usual approach — check whether the time is free, then write the booking — quietly fails under real traffic, because neither request can see the other. Here the database refuses the overlap outright.
Mechanism
An exclusion constraint over time ranges makes an overlapping booking impossible to store; temporary holds and time-zone-correct server scheduling sit on top of it.
Trade-off
Competing writes on the same resource serialise, so a rush on one popular slot is slower than a naive insert would be — and correct, which the naive insert is not.
